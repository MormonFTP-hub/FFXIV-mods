# PMP Viewer

Test a Penumbra mod without starting the game. The viewer opens a `.pmp` (or an unpacked mod folder), works out every file the game would ask for with the mod enabled, serves each one from the mod or the game data the way Penumbra does, and draws the result with **the game's own shaders**: the compiled shader code inside FFXIV's `.shpk` / `.shcd` files (and any the mod replaces), run on your GPU through the game's own pass structure. See [Game shaders](#game-shaders).

## Start it
Double-click **`PMP Viewer.exe`**. It opens in its own window, and closing the window quits it.
- Drop a `.pmp` onto the exe (or use Open with) to open that mod straight away.
- Starting it again while it's open just opens another window on the running viewer.
- The first start unpacks a small helper into `%LOCALAPPDATA%\PmpViewer`, so later starts are quicker.
- Caches go to `work\` next to the exe (or `%LOCALAPPDATA%\PmpViewer\work` if that folder isn't writable). A log is kept in `work\pmpviewer.log`.
- It finds the game through XIVLauncher's GamePath, then the usual SE/Steam folders. Set `PMPVIEWER_SQPACK` to a `...\game\sqpack` folder to override.
- It needs Microsoft Edge (part of Windows 11) for the window and the .NET 10 runtime for the helper. Without Edge it opens your default browser and a small Quit window instead.

Inside the viewer:
- Every `*/out/*.pmp` in the folder above the exe's (`E:\FFXIV-mods`) is listed in the Mod box.
- To open any other mod, drop a `.pmp` on the page or type a path (a `.pmp` or an unpacked Penumbra mod folder). Installed mods in Penumbra's mod folder work too, including Penumbra 1.7's single-`meta.json` layout.

From source: `python -P -E PmpViewer/server/app.py` (Python 3.11 with numpy and Pillow) serves it at http://127.0.0.1:8765/ (`?mod=<path>` opens a mod). In Claude's browser pane, use the `pmp-viewer` entry in `.claude/launch.json`. `Start PMP Viewer.cmd` does the same. Nothing is ever written to the game or to Penumbra.

Rebuild the exe with `python -P -E tools/build_exe.py` (needs PyInstaller and the .NET SDK). It compiles the helper into `build/`, leaves out the Dalamud UI libraries it never loads, and packs everything into `PMP Viewer.exe`.

## Your character
- **Paste Glamourer design**: in Glamourer, export or copy a design (or your character from the Actors tab) to the clipboard, then paste it. Whatever the design applies is used: race, clan, face, hair, skin / hair / highlight / eye colours, height, bust size, facial features, face paint, gear and its dyes. The clan sets the race, as in Glamourer, which leaves "Race" unticked in its designs. The design's **advanced colours** (Glamourer's parameters) replace the palette colours: skin, hair, highlights, each eye, lips, feature colour, face paint colour and opacity, face paint UV, muscle tone and limbal rings. Picking a swatch by hand overrides that one colour.
- **Face paint** (number, colour index 0-127 dark / 128-255 light, flipped): the game binds the character's face paint as the decal of whatever is drawn in the face slot, and the game shaders do the same. A face mod therefore shows your face paint the way the game will. A `character.shpk` face material with the decal key on gets the paint over its whole surface, because face paints are single-channel masks with full alpha. The problems list flags that material (Sora 1.1.0's face went dark grey-brown in game for this reason).
- Otherwise pick race and clan, then click the colour swatches. They offer the same palettes as the game's character creator, read from `human.cmp`, and the render uses the game's own shader colours for that palette entry.
- The height slider scales the model like the game: the clan's min/max from `human.cmp`, with the mod's RSP manipulations applied.
- The bust slider (women) scales `j_mune_l` / `j_mune_r` in their own axes, between the clan's BustMin and BustMax XYZ from `human.cmp` (RSP manipulations applied). 50 is about 1.0.

## Game shaders
The 3D view (renderer **Game shaders**, the default) comes from `apps/xivrender`, a D3D11 renderer that runs FFXIV's own compiled shaders. Nothing about a material is re-implemented: the game's code decides what every texture, colour-table row, shader key and constant does.
- **Shaders**: the `.shpk` named by each material, taken from the mod when it replaces it, else the game. The node is chosen with the game's selector over system, scene, material and sub-view keys (Penumbra's `ShpkFile.BuildSelector`); scene keys are set per draw like the game (skinned vs rigid, alpha clip when the material has a threshold).
- **Inputs**: every constant buffer is filled by member name from the reflection data the game's shader blobs still carry (`g_CameraParameter.m_ViewMatrix`, `g_AmbientParam.param.sh`, ...). `g_MaterialParameter` is the package's defaults overwritten by the material's constants; the colour table is uploaded as the raw half-float rows (8×32 Dawntrail, 4×16 legacy), after dyeing with Penumbra's own dye code and the game's `stainingtemplate*.stm`; samplers use the material's flags (address modes, LOD bias). `g_ShaderTypeParameter` is built from `common/graphics/*_shader_param.spm` (chara block at 32: Default / Hair / Legacy / Half lighting, subsurface, sheen, fur). Models upload their vertex streams as stored, with input layouts from the vertex declarations (8-weight Dawntrail skinning read as integers, as the shaders do); shape keys rewrite the index buffer, attributes hide submeshes, joint matrices go in view space (`TransformViewSkin`).
- **Passes**, in the game's order (light pre-pass renderer, `RenderTargetManager`): sun shadow map (`PASS_Z_OPAQUE`, shadow sub-view) → G-buffer (`PASS_G_OPAQUE`, 5 targets) with decals blended on top (`charactertattoo` alpha-blends albedo, `characterocclusion` multiplies) → GTAO (`compute/gtao*.shcd`, Intel's XeGTAO as the game compiles it) → shadow mask (`directionalshadow.shpk`) → light buffers (`directionallighting.shpk`, optional `cameralighting.shpk`) → composite (`PASS_COMPOSITE_OPAQUE`) → semi-transparency (the nearest transparent layer into its own G-buffer, lit with `SemiTransparency = 1`, then `PASS_COMPOSITE_SEMITRANSPARENCY` blended back to front; glass gets the scene colour and view positions it refracts) → tone curve (`ToneMapLut` / `ToneMapping.shcd`).
- **Exact by construction**: how a mod's models, materials, textures, colour tables, dyes, shader keys and replaced shaders look under a given light. That's why the metal-row `_id` problem shows as near-black armour (Gekko, Neon, Nurse-Pool), Black Cat's mirrored UDIM tiles show pink and black, hair is opaque above `g_AlphaThreshold` and blended below it, and so on, without any special-case code.
- **Scene settings, not taken from a game frame**: where the sun is and how bright, the ambient (L1 spherical harmonics), the reflection probe (sky colour above the horizon, ground colour below it, so metal picks up sunlit ground like in game), the camera light that keeps characters readable in game (`cameralighting.shpk` plus the per-draw `m_CameraLight` strength), exposure and the tone curve's white point (the game adapts exposure to the whole screen), fog and colour grading (off), and the GTAO radius (XeGTAO's defaults). These are the knobs to match in-game footage.
  - **Day** is fitted to in-game footage (patch 7.4, a Miqo'te in the Bygone Brass sets in open sunlight): front, side and back of the Fending set, with the Casting set held out. On the held-out frame the error dropped 72% from the old estimate, and the comparison is in `work/calibration/compare_day.png`. What's left is the zone's colour grade (the coat reads slightly olive against the game's reddish brown) and the player's own customisation. The other presets are still estimates for the game renderer.
  - **Calibrating the light** from your own footage (`tools/calibrate_light.py`): grab frames with `ffmpeg -ss <s> -i video.mp4 -frames:v 1 work/calibration/frames/t<s>.png`. Pick plain daylight shots without GPose lights or ReShade, of vanilla gear you can load. In the viewer, load that race and gear (my collection off unless the video has your mods), run `tools/calibrate_page.js` in the page, line the figure up with `cal.cam(...)` and `cal.shot(...)`, then `cal.save('<name>')`. Copy the two saved files to `work/calibration/state_<name>.bin` and `scene_<name>.json`, list the views in `work/calibration/views.json` (camera yaw, head row to ignore, overlay boxes, optional `holdOut`), and run `python -P -E tools/calibrate_light.py <renderer port> [iterations]` (the port is `window.pmpv.xr.port`). It aligns each frame (zoom, offset, camera orbit), fits sun, ambient, reflections and camera light, and writes `fit.json` and `compare.png`. Put the result into a preset's `xr` block in `viewer/app.js`.
- Things learnt from the game's shaders on the way: the world is right-handed with front faces counter-clockwise on screen (`j_te_l` sits at +X); depth is reversed (1 at the near plane); G-buffer normals are world-space; the scene colour is stored as sqrt(HDR); the hair two-pass split (opaque ≥ threshold, blended fringe ≥ 16/255); the iris ring term reads the eye colours' W (0 = plain irises, as in game), while face-paint UV scale/offset are the hair colours' W (ClientStructs' comments have these swapped); `g_ShapeDeformParam.x` must be -1 to turn Dawntrail's view-dependent shape deform off; the GTAO constants are XeGTAO's in the game's own order.
- Not drawn yet: bloom/glare, FXAA/TAA, fog, colour filter, sky, water, VFX; Dawntrail's seam connection between body parts (compute pass) is off; physics bones don't swing.
- Debug views (renderer CLI `--scene scene.json` with `"output"`): `gbuffer0..4`, `lightdiffuse`, `lightspecular`, `shadowmask`, `shadowmap`, `ao`, `hdr`, `semigbuffer*`, `semilight*`. `--dump shader/sm5/.../x.shcd` prints a shader's reflection and disassembly.
- **From the command line** (no page needed), for port pipelines:
  - `python -P -E tools/gs_render.py <mod.pmp | vanilla> <out.png>` renders a pack in GS. It resolves the pack like the page and poses it with the game's own animations (`--pose idle|pose1..4|walk|run|bind`, `--time`). It takes the page's subject options (`--design` for a Glamourer design, `--race/--face/--hair/--gear`, `--face-paint`, `--set "Group=Option"`, `--no-collection`), plus `--cam front|back|left|right|three-quarter|head|feet`, `--env day|neutral`, `--output gbuffer0..4|...` and `--swap <game path>=<file>` for quick A/B tests. Check posed renders, not just bind pose: Sora's jacket layers only slid through each other at the game's idle.
  - `python -P -E tools/check_pmp.py <mod.pmp>` prints the viewer's checks: Penumbra's reading of the manipulations, files missing from the pack, the problems list for one character, and the All races table. It takes the same subject options and exits 1 on errors.

## What it shows
- **3D view**: the character (or monster, demihuman, weapon) with the mod on. Poses are the game's own animations for the character's race: the idle (still or animated), the four /cpose stances, walk and run. They're decoded from `chara/human/<race>/animation/a0001/bt_common/...pap` (Havok spline-compressed). Highlander men and Lalafell women fall back to Midlander men and Lalafell men, as in game. Test poses (bind, arms down, arms up, sit) are still there. Skinning is done on all 8 Dawntrail weights, with the racial deformer applied per bone the way the game does when a race wears another race's model.
  - **Colour by source**: green = file served by the mod, grey = vanilla, blue = file swap, amber = from your Penumbra collection, magenta = missing material.
  - **Colour by slot**, wireframe, skeleton.
  - **Weights of selected bone**: heat map; magenta = weighted to a bone the loaded skeletons don't have.
  - **Show hidden parts**: draws what the EQP / IMC data hides as a red wireframe.
  - **Vanilla side by side**: the same character without the mod, next to it.
  - Double-click a mesh to find its model in the load trace.
- **Models** (side panel): each slot's model, where it came from, whether another race's model is reshaped for it, why a slot is hidden, and chips for every submesh attribute (`atr_*`) and shape key (`shp_*`, `shpx_*`). Click a chip to flip it.
- **Problems**:
  - missing files, and files the mod maps but doesn't contain
  - models weighted to bones no loaded skeleton has, and weights pointing outside the bone table
  - unparsable files, missing IMC variants
  - a mod material that mostly uses a fully metallic colour-table row. In game metal gets no diffuse light and looks dark, which is usually an inverted `_id` green.
  - vertex colour set 0 near black on a Dawntrail `character.shpk` mesh. The shader multiplies the surface by it, which is what turned Mantis pitch black in game.
  - a mesh whose UVs leave the 0..1 tile while its material samples with mirror or clamp addressing. The game then mirrors or smears the texture there. Black Cat's suit came out mirrored in game this way: its materials copy the vanilla e0800 template, whose samplers use Mirror, and its UVs sit on tiles u 1..3, v -1.
  - manipulations Penumbra's own reader drops
- **Load trace**: every request in order (skeletons, models, materials, textures) with its source (mod file + option, swap, game, missing). It also shows the EQDP race chain, the IMC entry (material folder, attribute mask), the EST skeleton and the deformer.
- **Mod files**: every redirection in the mod, marked when this preview actually requests it. Files never requested by any race or variant are dead weight or a wrong path.
- **Meta**: the combined EQP flags (and which piece each slot's bits come from), the active manipulations, and conflicts between the mod's own options.
- **Materials**: the baked colour / normal / roughness-metal maps per material, the shader, and the texture behind each sampler.
- **All races**: the current gear resolved for all 18 race/gender combinations. For each slot it shows whether the race gets the mod's model, another race's model through the deformer, the vanilla model, or nothing.

## How it resolves (sources)
- **Your collection** (the **my collection** checkbox, on by default): the opened mod is layered over every enabled mod of your own Penumbra collection (the one assigned to Yourself, else Default), with the options you picked, as Penumbra's collection cache does it. The opened mod counts as highest priority, then the rest by priority; the first entry per file, swap and manipulation wins. So a custom skeleton (Illusio Vitae), a face mod, Bibo+ skin or another gear mod you run alongside it shows here too, and files from it show as COLLECTION in the load trace, naming the mod and option. The collection is read once at start-up and again whenever Penumbra rewrites the collection file. Listing every mod's files takes a while on a cold disk. Untick the box to see the mod on its own. (`server/collection.py`) An installed copy of the opened mod (same mod name) is always left out, both from this layering and from the material/texture fallback, so a file the `.pmp` forgot to ship shows as missing instead of being quietly filled from your installed copy.
- **Face materials** resolve the way the game does: the face id of the loaded face model goes into the material's folder *and* file name, whatever id the material name carries. A face model for face 5 naming `/mt_c0201f0001_x.mtrl` is looked up as `face/f0005/material/mt_c0201f0005_x.mtrl`, so a face mod that ships its materials only for face 1 shows them missing on faces 2-5, as it is invisible there in game. (`server/resolve.py` `human_material_path`)
- **Options**: groups in descending priority (ties: the later group wins), Multi options by option priority, `default_mod.json` last; the first entry per game path / manipulation wins; Files beat FileSwaps; swap targets come straight from the game. Imc groups write the default entry's attribute mask XOR the selected options' masks. (Penumbra `Mods/Mod.cs`, `SubMod.cs`.)
- **Model race**: own race if its EQDP model bit is set, else one `Fallback()` step if that race has the bit, else c0101 (Penumbra `ResolveContext.PathResolution.cs`, `Race.cs`).
- **Materials**: `<model folder>/material/v<IMC MaterialId>/<name>`; skin materials (`mt_c####b####_*`) go to the wearer's nearest skinned race. Face and ear materials have no variant folder. Hair materials follow `MaterialHandling.cs`.
- **EQP**: Penumbra's `EqpCache` (the game's GetEqpFlags): head, hands and legs bits come from the body set when the body doesn't show them, then the glove and boot length passes run. Flag → attribute pairs come from the xivmodding.com visibility tables (pre-Dawntrail, so treat edge cases as approximate).
- **IMC** attribute mask bit k shows `atr_<mv|tv|gv|dv|sv>_<a+k>`.
- **Boots and the legs' knee/shin parts**: `FeetHideCalf` hides the shin (`atr_sne`). `FeetHideKnee` hides the knee (`atr_hiz`) only together with `FeetHideCalf`, as knee-high boots carry both. On its own (264 sets) it hides nothing. This was checked against 7.4 footage: the Bygone Brass Boots of Casting show the shorts' knee part in game, and the Sabatons of Striking hide the shin but not the knee.
- **EST** picks the face, hair, head and body skeletons. Skeletons are merged onto the base one at their shared root bone. Havok tagfile versions 3 (the game's) and 5 (Havok 2014 SDK, which custom skeletons such as Illusio Vitae use) are read.
- **WebGL preview** (renderer select, and every diagnostic colouring): the older approximation, baked from the real textures. Vertex colour set 0 multiplies `character.shpk` / `characterlegacy.shpk` surfaces. Specular strength comes from the mask's red channel times the colour table's specular colour.
  - Textures are sampled with each material's own address modes, like the game: sampler flags bits 0-1 = U, bits 2-3 = V; 0 wrap, 1 mirror, 2 clamp, 3 border, drawn as clamp (Penumbra `SamplerFlags`). With UVs outside 0..1, mirror flips the texture on every odd tile.
  - Lighting presets: **Neutral studio**, **Day**, **Dusk**, **Night**, **Indoor** and **Unlit** (exact texture colours). In game, light, haze and colour grading change with zone, weather and time, so pick the preset closest to where you look. **Night** was fitted to two in-game screenshots: dim neutral light, light distance haze and the game's night colour grade, which desaturates without lifting blacks. It came within about 5 RGB units on Peni's yellow and orange cloth, and Jotaro's white coat stays neutral grey, as in game. (A blue moonlight made it navy.) For the WebGL preview, Day and Dusk are still estimates; the game renderer's Day is fitted (see **Game shaders**).
  - The sun or moon casts shadows, like the game's: a cap brim shades the face, an open coat the shirt. **Light from** and **height** set where it stands. Match them to an in-game shot before comparing, because the light's direction decides what's in shadow. Under Jotaro's cap, with the moon to his side and behind, his face gets about an eighth of the light his hand does in game. The darkness there is shadow, not the material.
  - **Sky light** scales the light that fills the shade. The game's shade is deep: the shaded side of Jotaro's white coat got 1/9 of its sunlit side next to a cliff. Lower the slider for spots where cliffs, trees or roofs block the sky (about 30-45% for that shot). Day is set for open ground.
  - Ambient occlusion (three.js GTAO, like the game's HBAO) darkens creases and the space under brims. Its normal pass keeps alpha cut-outs, so hair cards don't cast square halos. It's off for Unlit, the diagnostic colourings and wireframe; the checkbox turns it off entirely.
  - `characterlegacy.shpk` keeps the pre-Dawntrail meaning of its textures even when its colour table is in the Dawntrail format:
    - mask (`_s`): red = specular, green = gloss
    - roughness = 1 − gloss, screen-blended with 1 − (row shininess)/16 (TexTools' reading)
    - no metal, and mask blue isn't occlusion
    - The colour table's roughness field is ignored. Snake's port had 0 there, which made the viewer draw a mirror finish where the game shows matte cloth.
  - Dawntrail `character.shpk`: `_id` R picks the colour-table pair (R/17), G = 255 the pair's first row, 0 its second (Penumbra's exporter and TexTools' converter agree). `_mask` G roughness, B occlusion; `_norm` B opacity.
  - `skin.shpk` tints `_base` by the skin colour through `_norm` B. `hair.shpk` mixes hair and highlight colour through `_norm` B. `iris.shpk` tints by eye colour through `_mask` B.
  - In the preview, dye, the game's lighting, subsurface, sheen and vertex-colour effects are not reproduced and occlusion shaders aren't drawn; the game shaders do all of these.

## Not covered
- Physics (`.phyb`), VFX, sounds; mounts and minions show in bind pose. Bones the game simulates (breasts `j_mune_*`, hair, skirt, tail, ears) are drawn where the animation puts them. In game they swing and sag with movement, which can squash a chest that's heavily weighted to `j_mune` (Black Cat's is).
- Other mods' physics and animations: collection mods are layered in (see **Your collection**), but `.phyb` and `.pap` files from them aren't simulated or played.
- Weapons on a character (weapons can be viewed on their own as the Weapon subject).
- Racial scaling (RSP), body-type (EVP), Atch and GMP visor manipulations are listed but not applied.
- Your own character's look is only what you set or paste: skin, hair and eye colours, face paint and so on come from the swatches or a Glamourer design, not from the game.
- What the game does with a bone missing from every loaded skeleton isn't documented. The viewer leaves those vertices in the bind pose and reports them as errors.

## Layout
- `server/launcher.py`: the exe's entry point (server + Edge app window, single instance). `tools/build_exe.py`: builds the exe.
- `server/app.py`: HTTP server and API. `pmp.py`: mod options and merging. `resolve.py`: the load trace and scene. `meta.py`: EQP/EQDP/IMC/EST. `visibility.py`: what the EQP and IMC data hide. `skeleton.py`: sklb, partial skeletons, racial deformer. `shade.py`: material bake. `game.py`: game data and caches.
- `tools/xivrender`: the game-shader renderer (C#, D3D11 via TerraFX, Lumina, Penumbra.GameData), built to `apps/xivrender` (`dotnet build -c Release -o ../../apps/xivrender`). The server starts it on demand (`/api/render_info`); the page talks to it directly over HTTP on a local port (`/scene` once, `/frame` per view with camera, light and skinning matrices, raw RGBA back). `Renderer.cs` resources and targets, `Frame.cs` constants and binding, `Passes.cs` the frame, `Gtao.cs` ambient occlusion, `Assets.cs` / `XivTex.cs` / `Models.cs` game files, `Shaders.cs` packages and nodes, `Reflect.cs` shader reflection, `Server.cs` HTTP.
- `tools/xivserve`: a long-running C# helper (Lumina + Penumbra's own `MdlFile`/`MtrlFile` readers), built to `apps/xivserve`. Rebuild with `dotnet build -c Release -o ../../apps/xivserve` in that folder.
- `viewer/`: the page (three.js 0.170 vendored from `Jubilee/apps/npm/three.tgz`).
- `work/`: extracted game files, unpacked mods and caches (safe to delete).
